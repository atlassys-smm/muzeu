# Навигация для агентов

## Назначение проекта

Рабочая база подготовки заявки на закупку цифровой экосистемы Театрального музея им. А. А. Бахрушина. Статический сайт MkDocs Material на русском языке. Здесь готовят предложение Заказчику, а не разрабатывают саму экосистему.

## Как начинать отдельную задачу

1. Проверь `git status --short`, сохрани чужие незакоммиченные изменения.
2. Выбери нужную папку по таблице ниже. Для работы над предложением прочитай также `docs/proposal/AGENTS.md`.
3. Открой только целевую страницу и её `criterion.md`; для проверки результата — также `compliance.md`.
4. Читай конкретные пункты первоисточников по ссылкам из карточки. Не загружай все ТЗ, все матрицы, DOCX и `verification/*.txt` для обычной локальной задачи.
5. Если данных не хватает, найди нужный пункт через `rg`, затем прочитай его контекст. Сохраняй оговорки и ограничения источника.

## Источники требований

- `docs/technical-specification.md` — оглавление ТЗ и титульные сведения.
- `docs/technical-specification/01.md` … `22.md` — разделы ТЗ. Разделы 9 и 15 имеют обзор и отдельные подразделы: `09-01.md` … `09-13.md`, `15-01.md` … `15-07.md`.
- Внутри файла могут находиться более глубокие подпункты. Например, 9.10.8 находится в `09-10.md`, а не в отдельном файле.
- `docs/technical-specification/appendix-01.md` … `appendix-12.md` — приложения ТЗ.
- `docs/evaluation.md` — оглавление порядка оценки.
- `docs/evaluation/01.md` — заказчик и закупка; `02.md` — веса и шкалы; `03.md` — подробный состав предложений и основания нулевой оценки.
- В `docs/evaluation/03.md` якоря `quality-1` … `quality-5` ведут к пунктам 2.1.1 … 2.1.5.

Для сквозных вопросов обычно нужны: `01.md` (1.6, измеримость), `08.md` (сценарии), `11.md` (API и обмен), `13.md` (дизайн и доступность), `15-04.md` (ПДн), `appendix-01.md` (проверки сценариев). Открывай их только по необходимости.

Это дословно перенесённые источники. Не редактируй их формулировки под наше решение. Интерпретации, выявленные расхождения и проектные решения записывай в `docs/proposal/`. Требование пользователя о точности имеет приоритет над стилистической правкой.

## Устройство сайта

| Файл или папка | Назначение и когда читать |
| --- | --- |
| `mkdocs.yml` | Меню, тема, расширения, CSS, JS и hooks. Новая страница должна попасть в `nav`. |
| `overrides/main.html` | Раскрытое левое меню предложения на главной сайта и всех страницах `proposal/`; строится из `nav`, не содержит отдельного списка страниц. |
| `docs/stylesheets/extra.css` | Таблицы, адаптивное меню и оформление всплывающих выдержек. |
| `hooks/source_references.py` | При сборке добавляет открытие источников в новой вкладке, выдержки и якоря сценариев `scenario-c-04` и т. п. |
| `docs/javascripts/source-previews.js` | Предпросмотр при наведении/фокусе; закрытие по Escape. Выдержки встроены в HTML, сетевых запросов нет. |
| `docs/javascripts/document-redirects.js` | Переходы со старых закладок единой страницы ТЗ на отдельные разделы. Генерируемый файл. |
| `scripts/import_documents.py` | Повторный импорт DOCX и эталоны. Не запускай для обычного редактирования предложения. |
| `scripts/split_documents.py` | Разбиение импортированных источников, навигация и старые закладки. Прямой запуск тоже запускает импорт. |
| `scripts/verify.py` | Проверка текста источников, числа таблиц/формул/изображений и контрольных сумм. Не проверяет содержательную полноту предложения. |
| `verification/` | Эталоны и протокол переноса; `pages.json` — порядок фрагментов источников. Не переписывай эталоны ради прохождения проверки. |
| `documents/` | Локальные исходные DOCX, исключены из Git. В обычной работе достаточно перенесённых источников. |
| `homepage/` | Отдельный HTML/CSS/JS-макет главной Г-01–Г-09; запуск и общие данные описаны в `homepage/README.md`. Не входит в MkDocs. |
| `site/`, `.venv/` | Сборка и окружение, исключены из Git. Не редактируй содержимое `site/` вручную. |

## Команды

Используй существующее `.venv`; установка описана в `README.md` и `requirements.txt`.

```sh
.venv/bin/mkdocs build --strict
.venv/bin/python scripts/verify.py
.venv/bin/mkdocs serve --dev-addr 127.0.0.1:8000
```

Локальный сайт: `http://127.0.0.1:8000/`. Прежде чем запускать ещё один сервер, проверь существующий. Ошибка подключения из ограниченной среды не доказывает, что сервер упал; проверяй в разрешённом сетевом контексте.

После изменения Markdown или конфигурации достаточно строгой сборки; после изменений источников/импорта/обработки источников — также `scripts/verify.py`. Для меню и popover проверь соответствующую страницу в браузере. Проверка текста нормализует пробелы и не заменяет содержательное чтение требований.

При коммите не включай `site/`, `.venv/`, DOCX и временные файлы. Не делай коммит без запроса пользователя или ранее данного указания в текущей задаче. Обновляй эту карту, если меняются структура или правила проекта.
