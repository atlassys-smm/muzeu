# Критерий и оценка

**Предложение №3: Билетный контур и квесты.** Рабочая карточка для подготовки заявки по [п. 2.1.3](../../evaluation/03.md#quality-3). Обязательный состав и шкала приведены по документам закупки; пояснения и матрица проверки помогают подготовить материалы.

## Что оценивается

Предложение по составу и содержанию выполнения работ по пункту 9.5 (Билетный контур) и подпункту 9.10.6 (Квесты и маршруты) Технического задания, в части конкретных технических решений (демонстрирующее понимание предмета выполняемых работ)

| Параметр | Значение |
| --- | --- |
| Критерий | Качественные, функциональные и экологические характеристики объекта закупки |
| Значимость критерия | 60% |
| Показатель | Качественные характеристики объекта закупки; значимость 100% |
| Детализирующий показатель | №3; значимость 20% |
| Шкала | 100 или 0 баллов |

Источник: [таблица критериев и шкал, раздел II](../../evaluation/02.md) и [Порядок оценки, III, п. 2.1.3](../../evaluation/03.md#quality-3).

## Шкала оценки

При наличии предложений по составу и содержанию работ заявке присваивается:

- 100 баллов – наличие всех алгоритмов и описания, демонстрирующих понимание сквозных сценариев.

- 0 баллов – отсутствие хотя бы одного алгоритма или формальное перефразирование ТЗ.

.

По разделу III баллы членов комиссии усредняются и учитываются со значимостью соответствующих показателей. Расчётный максимальный вклад одного предложения в итоговую оценку — **12 баллов из 100**: `100 × 20% × 100% × 60%`. Для всех пяти предложений — до 60 итоговых баллов. Это расчёт по указанным весам, а не дополнительная шкала; промежуточные уровни за частично выполненный комплект документом не установлены.

## Обязательный состав предложения

Ниже воспроизведён состав по п. 2.1.3 порядка оценки. Каждый перечисленный элемент должен находиться в материалах заявки.

1.  **Алгоритм (блок-схема)** действий пользователя при сканировании QR-кода для получения билета:

    - открытие камеры/сканера;

    - распознавание QR-кода;

    - проверка статуса билета (активен, использован, отменён);

    - отображение QR-билета и информации о событии;

    - работа в офлайн-режиме (кэширование);

    - защита от доступа к чужому билету.<br>
      Требования – согласно **п. 9.5** и сценарию **С-04** ТЗ.

2.  **Алгоритм (блок-схема)** действий пользователя при прохождении квеста с использованием QR-кодов:

    - получение задания;

    - сканирование кода в определённой локации;

    - подтверждение выполнения (ответ на вопрос, геолокация);

    - продвижение по маршруту;

    - сохранение прогресса и получение награды.<br>
      Требования – в соответствии с **п. 9.10.6** ТЗ.

3.  **Алгоритм (блок-схема)** действий администратора при создании и управлении квестами:

    - создание нового квеста / маршрута;

    - добавление заданий с условиями (привязка к QR-кодам, локациям);

    - установка правил прохождения, ограничений, наград;

    - публикация и управление версиями;

    - просмотр статистики прохождения.<br>
      Требования – согласно **п. 9.10.2–9.10.6** ТЗ.

4.  **Описание последовательных шагов выполнения работ** по интеграции сканирования QR-кодов в мобильное приложение и билетный контур, а также по реализации административной панели для управления квестами (архитектура, используемые API, методы обеспечения идемпотентности и защиты от дублей).

## Когда выставляется ноль {#когда-выставляется-ноль}

По [п. 2.1.3](../../evaluation/03.md#quality-3):

1. отсутствие хотя бы одного алгоритма или формальное перефразирование ТЗ,

2. предложение участника закупки перефразирует Техническое задание,

3. участник закупки указывает что выполнит работы надлежащим образом в соответствии с Техническим заданием,

4. предложение участника нарушает законодательство Российской Федерации.

5. предложение участника представлено не в полном объеме.

Предложение предоставляется в свободной форме. Порядок оценки прямо указывает: отсутствие информации по этому детализирующему показателю само по себе не является основанием признать заявку не соответствующей требованиям. Однако оно лишает возможности получить баллы по соответствующему показателю.

## Особенности проверки

В порядке оценки перечислены активный, использованный и отменённый билет. Сценарий С-04 ТЗ дополнительно включает возвращённый билет — его также включаем в проверку. Различаем пользовательское сканирование QR-кода и контроль прохода сотрудником: нельзя подменять требуемую пользовательскую схему схемой турникета. Доступность активного билета по С-04 обязательна; выбранный способ интеграции должен учитывать реальные возможности внешней системы.
