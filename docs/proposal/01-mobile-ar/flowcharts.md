# Блок-схемы

Приложение к [материалам заявки](result.md) по [п. 2.1.1 порядка оценки](../../evaluation/03.md#quality-1). Схемы описывают предлагаемое решение для последующей реализации и согласования; музейный сюжет не влияет на общий порядок обработки.

## 1. Взаимодействие посетителя с приложением {#user-flow}

```mermaid
%%{init: {"flowchart": {"useMaxWidth": false}}}%%
flowchart TD
    start[Выбор AR-сценария] --> package{Полный пакет доступен?}
    package -->|Нет| network{Есть сеть?}
    network -->|Да| download[Загрузка и проверка<br/>версии и файлов]
    download --> loaded{Загрузка успешна?}
    loaded -->|Да| device
    loaded -->|Нет| unavailable[Сообщение об ошибке:<br/>повтор или другой<br/>сценарий]
    network -->|Нет| unavailable
    unavailable -->|Повтор| package
    unavailable -->|Выход| stop[Завершение без результата]
    package -->|Да| device{Устройство поддерживает<br/>AR?}
    device -->|Да| permission{Камера разрешена?}
    device -->|Нет| alternative[Доступная альтернатива:<br/>карточки и медиаматериалы]
    permission -->|Нет| alternative
    permission -->|Да| scan[Локальное распознавание<br/>изображения, метки или QR]
    scan --> found{Цель найдена в каталоге?}
    found -->|Нет| hint[Подсказка: освещение,<br/>расстояние, положение]
    hint -->|Повтор| scan
    hint -->|Альтернатива| alternative
    found -->|Да| media[Показ 3D, текста, аудио и<br/>видео по сценарию]
    media --> action[Интерактивное действие<br/>или ответ]
    media -->|Потеря трекинга| pause[Пауза и повторное<br/>наведение]
    pause --> scan
    alternative --> action
    action --> save[Запись события и<br/>предварительного<br/>прогресса на устройстве]
    save --> more{Есть следующие этапы?}
    more -->|Да| mode{Режим AR?}
    mode -->|Да| scan
    mode -->|Нет| alternative
    more -->|Нет| local[Локальное завершение:<br/>результат ожидает<br/>проверки]
    local --> auth{Есть подтверждённый сеанс<br/>владельца?}
    auth -->|Нет| login[Вход и подтверждение<br/>привязки локальной<br/>попытки]
    login -->|Успех| online
    login -->|Отложен| waiting[Очередь сохранена; баллы<br/>не подтверждены]
    auth -->|Да| online{Есть сеть?}
    online -->|Нет| waiting
    waiting -->|Сеть и сеанс восстановлены| auth
    online -->|Да| send[Отправка событий с<br/>постоянными event_id]
    send --> response{Ответ системы}
    response -->|Тайм-аут или временный сбой| waiting
    response -->|Отклонено или нужна проверка| reason[Причина и статус;<br/>подтверждённый прогресс<br/>сохранён]
    response -->|Прогресс принят, начисление ожидается| pending[Результат сохранён;<br/>ожидание лояльности]
    pending --> refresh[Обновление статуса без<br/>нового основания награды]
    refresh --> response
    response -->|Подтверждено| result[Результат в профиле,<br/>достижения и единый<br/>баланс]
    result --> finish[Завершение]
    reason --> finish
    action -->|Прекратить| exit[Сохранение промежуточного<br/>прогресса и события<br/>прекращения]
    exit --> finish
```

Пакет включает контент и доступную альтернативу. Ошибки загрузки позволяют повторить операцию или выбрать другой доступный сценарий. Согласованный способ распознавания задаётся для каждой цели; QR выбирает контент и не подтверждает физическое присутствие. События ставятся в очередь по мере действий, отправляются при наличии сеанса и сети; итоговый блок отправки также обеспечивает досылку накопленного остатка.

Гость может просматривать публичные материалы. Начисление возможно только после идентификации и серверной проверки. Прекращение сохраняет промежуточные данные; подтверждение такого прогресса использует тот же механизм синхронизации. Условие завершения альтернативного пути задаётся сценарием. Разрешение камеры и маркетинговые согласия не смешиваются.

Основания: [9.10.8](../../technical-specification/09-10.md#дополненная-реальность), [С-11](../../technical-specification/08.md#scenario-c-11), [9.8](../../technical-specification/09-08.md#мобильное-приложение).

## 2. Обработка AR-событий информационной системой {#system-flow}

```mermaid
%%{init: {"flowchart": {"useMaxWidth": false}}}%%
flowchart TD
    subgraph client[Мобильное приложение]
        recognize[Локальное распознавание и<br/>действие пользователя]
        queue[Локальная очередь:<br/>event_id, попытка,<br/>версия, этап, действие]
        recognize --> queue
    end
    queue --> request[API: приём события по<br/>защищённому каналу]
    subgraph server[Сервер AR и<br/>интеграционный контур]
        request --> session{Сеанс действителен?}
        session -->|Нет| unauthorized[Ошибка авторизации:<br/>восстановить сеанс<br/>владельца]
        session -->|Да| owner{Попытка принадлежит<br/>пользователю?}
        owner -->|Нет| deny[Отказ с причиной, без<br/>начисления]
        owner -->|Да| consent{Доступ и основания<br/>обработки допустимы?}
        consent -->|Нет| deny
        consent -->|Да| duplicate{event_id уже<br/>зарегистрирован?}
        duplicate -->|Да| payload{Данные совпадают?}
        payload -->|Нет| conflict[Конфликт идентификатора<br/>события]
        payload -->|Да| previous[Возврат сохранённого<br/>решения и текущего<br/>статуса]
        duplicate -->|Нет| validate{Версия, порядок, действие<br/>и ограничения допустимы?}
        validate -->|Нет| rejected[Запись отказа либо<br/>направления на проверку]
        validate -->|Да| transaction[Транзакция: уникальное<br/>событие, прогресс и<br/>исходящая очередь]
        transaction --> reward{Достигнуто условие<br/>награды?}
        reward -->|Нет| accepted[Ответ: подтверждённый<br/>прогресс]
        reward -->|Да| basis[Команда с уникальным<br/>ключом основания награды]
        transaction --> analytics[Очередь аналитики:<br/>запуск, этап, завершение,<br/>отказ, ошибка]
        transaction --> profile[Доставка прогресса в<br/>профиль]
    end
    subgraph loyalty[Единый контур лояльности<br/>и достижений]
        basis --> once{Основание уже обработано?}
        once -->|Да| old[Возврат существующей<br/>операции]
        once -->|Нет| apply[Атомарное начисление или<br/>достижение и журнал<br/>операции]
        old --> confirmation[Подтверждение операции]
        apply --> confirmation
    end
    basis -->|Временный сбой| retry[Сохранить в очереди и<br/>повторить с тем же ключом]
    retry --> basis
    confirmation --> profile
    profile --> status[Ответ или последующее<br/>чтение: прогресс,<br/>достижения, баланс]
    accepted --> status
    previous --> status
```

Создание онлайн-попытки выполняется отдельным авторизованным запросом до отправки её событий. Для локальной попытки сервер сначала устанавливает соответствие идентификаторов после проверки владельца и допустимости прохождения. Схема показывает обработку одного события после этого сопоставления.

Проверка `event_id` на схеме поясняет алгоритм; защиту от гонки обеспечивает уникальное ограничение внутри транзакции. При одновременных запросах проигравшая транзакция читает уже сохранённое решение. Запись исходящей команды создаётся атомарно с прогрессом, а её фактическая доставка выполняется после фиксации транзакции. Временный сбой любого получателя — лояльности, профиля или аналитики — оставляет сообщение в очереди с повтором и наблюдаемым статусом. Постоянная ошибка фиксируется для разбора и не вызывает бесконечных повторов.

Уникальность события защищает от повторной доставки, уникальность основания награды — от повторного начисления через новое событие или новую попытку. Пример и состав ключей приведены в [описании результатов](result.md#results). Запрос клиента не содержит доверенной суммы баллов: её рассчитывает сервер по правилу. Проверка и аннулирование спорного результата выполняются уполномоченным сотрудником с причиной и журналом; операция отмены связана с исходным начислением.

Основания: [9.8.1](../../technical-specification/09-08.md#редизайн-и-доработка-мобильного-приложения), [9.10.10](../../technical-specification/09-10.md#защита-от-злоупотреблений), [9.10.11](../../technical-specification/09-10.md#аналитика), [11.4–11.5](../../technical-specification/11.md#требования-к-api-и-интеграционным-контрактам).
