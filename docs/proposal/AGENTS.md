# Работа над предложением

Дополнение к корневому `AGENTS.md`. Применяется к `docs/proposal/`.

## Страницы каждой папки

| Файл | Назначение |
| --- | --- |
| `criterion.md` | Что оценивается, обязательный комплект, условия максимума/нуля, ссылки на ТЗ, особенности и расхождения источников. |
| `compliance.md` | Наш план проверки будущего результата: методы, ожидаемые подтверждения и журнал. |
| `result.md` | Само предложение для Заказчика в составе заявки. |
| `flowcharts.md` | Приложение с блок-схемами, только у предложений 1–4. |
| `screens.md` | Подготовительный разбор экранов, сущностей, атрибутов и действий главной страницы; только у предложения 5. |
| `references.md` | Дизайн код: публичные материалы бренда музея и реестр недостающих исходников; только у предложения 5. |
| `reference-sites.md` | Референсные сайты: рейтинг пользователя, анализ решений и выбранное направление; только у предложения 5. |
| `content.md` | Реальные данные для наполнения главной: события, коллекции, объекты, новости, промо, товары и контакты с источниками; только у предложения 5. |
| `mockups.md` | Приложение с макетами, только у предложения 5. |
| `05-homepage-design/data/*.json` | Данные для подключения к макету: события, товары, предметы коллекции, объекты, новости, промо, навигация, организация и справочники. Схема и пример подключения — в `content.md#json-data`. |
| `05-homepage-design/assets/content/` | Локальные изображения расширенной подборки; пути, источники, размеры и оговорки указаны в JSON. Ранее собранные изображения остаются в `assets/references/`. |

На момент создания инструкций `criterion.md` и `compliance.md` заполнены; `result.md` пусты; приложения содержат только перечни будущих материалов. Перед работой проверь фактическое состояние целевой страницы. Не заполняй другие страницы автоматически.

## Минимальный контекст для задачи

- «Напиши предложение №N»: `criterion.md`, нужные пункты по его ссылкам, затем целевой `result.md`; сверяй готовый комплект по `compliance.md`.
- «Сделай блок-схему»: `flowcharts.md`, соответствующий обязательный элемент из `criterion.md`, связанные пункты ТЗ; не нужно читать остальные четыре предложения.
- «Сделай макет»: `05-homepage-design/mockups.md`, его `criterion.md`, 9.1.3 и применимые требования раздела 13; проверь наличие брендбука и утверждённого макета.
- «Проверь результат»: `result.md`, относящиеся к нему приложения, `criterion.md`, `compliance.md`; открывай источники по проверяемым строкам.
- «Измени меню/ссылки/предпросмотр»: файлы инфраструктуры из корневой карты; не перечитывай содержание всего ТЗ.

## Содержание и стиль

- Пиши по-русски, предметно, без формального пересказа ТЗ и обещания «выполним всё по ТЗ» вместо собственных решений.
- В заявочном результате описывай конкретные алгоритмы, данные, взаимодействия, состояния, отрицательные ветви и результат. Не представляй ещё не реализованную систему как уже испытанную.
- Карточки краткие: максимум каждого предложения — **12 итоговых баллов**, всех пяти — 60. Пользователь попросил не повторять веса 60%/100%/20% и формулы в каждой карточке.
- Условия шкалы источника — 100 либо 0 по каждому детализирующему показателю. Не смешивай это с 12 итоговыми баллами и не изобретай промежуточную шкалу. Решение комиссии не подменяется нашей проверкой.
- В матрицах `О-N-XX` — обязательный комплект и содержание по порядку оценки; `Т-N-XX` — связанные требования ТЗ; `Ф-N-XX` — финальная внутренняя проверка. Методы подтверждения — наша методика, а не новые условия закупки.
- Статус «Соответствует» ставь только после просмотра фактических материалов с точной ссылкой на файл, версию и фрагмент. Отсутствие данных или согласования не считай выполненной проверкой.
- Не превращай требования приёмки будущей системы в якобы обязательные готовые производственные результаты уже на стадии подачи заявки.

## Ссылки на источники

- Конкретный пункт ТЗ или порядка оценки — ссылка на нужную страницу и существующий якорь, а не просто жирный номер.
- Пример: `[п. 9.10.8](../../technical-specification/09-10.md#дополненная-реальность) ТЗ`.
- Слово «ТЗ» рядом остаётся обычным текстом. Не добавляй вторую ссылку на весь документ. Не ссылайся на весь документ при каждом общем упоминании.
- Состав предложения №N: `[п. 2.1.N](../../evaluation/03.md#quality-N)`; подставь номер 1–5.
- Сценарий: `[С-04](../../technical-specification/08.md#scenario-c-04)`; якорь формируется hook при сборке.
- Для диапазона пунктов указывай понятные ссылки на его границы или отдельные пункты; не подменяй их случайным соседним разделом.
- Markdown-ссылки пиши относительно файла, без `localhost` и абсолютных путей компьютера. Новая вкладка и всплывающая выдержка добавляются hook автоматически. Для оглавлений целых документов popover отключён.
- Извлекай выдержки дословно из источника. Не вписывай нашу интерпретацию в popover источника.

## Известные расхождения и зависимости

- Предложение №2: порядок оценки, п. 2.1.2, требует минимум два AR-маршрута с восемью заданиями каждый. В ТЗ 9.10.12 минимум восемь связанных заданий прямо указан для игровых маршрутов; число точек каждого AR-маршрута согласуется в ЧТЗ к КТ-2. Не отождествляй задания и AR-точки и не скрывай расхождение. Подробности в `02-ar-routes/criterion.md`.
- Предложение №1: порядок оценки упоминает защиту от дублей со ссылкой на 9.10.11; в ТЗ это аналитика, а защита от злоупотреблений — 9.10.10. Учитывай оба пункта и сохраняй различие источников.
- Предложение №3: порядок оценки называет активный, использованный и отменённый билет; С-04 ТЗ также требует возвращённый. Покупка не должна безусловно требовать предварительной активации ЛК; учитывай оговорки 9.3.
- Предложение №4: повторное прохождение викторины и повторная доставка одного запроса — разные случаи. Не запрещай все повторные попытки или награды вопреки настраиваемым правилам.
- Предложение №5: ТЗ ссылается на ранее утверждённый макет главной и брендбук. Их наличие не подтверждено. Не утверждай соответствие неполученным материалам.

Перед финальным результатом: проверь полноту по целевой матрице, ссылки и `mkdocs build --strict`. Не требуется повторно читать все источники для малой правки.
