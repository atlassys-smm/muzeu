# Критерий и оценка

**Предложение №4: Викторины.** Рабочая карточка для подготовки заявки по [п. 2.1.4](../../evaluation/03.md#quality-4). Обязательный состав и шкала приведены по документам закупки; пояснения и матрица проверки помогают подготовить материалы.

## Что оценивается

Предложение по составу и содержанию выполнения работ по пункту 9.10.7 (Викторины) Технического задания, в части конкретных технических решений (демонстрирующее понимание предмета выполняемых работ)

| Параметр | Значение |
| --- | --- |
| Критерий | Качественные, функциональные и экологические характеристики объекта закупки |
| Значимость критерия | 60% |
| Показатель | Качественные характеристики объекта закупки; значимость 100% |
| Детализирующий показатель | №4; значимость 20% |
| Шкала | 100 или 0 баллов |

Источник: [таблица критериев и шкал, раздел II](../../evaluation/02.md) и [Порядок оценки, III, п. 2.1.4](../../evaluation/03.md#quality-4).

## Шкала оценки

При наличии предложений по составу и содержанию работ заявке присваивается:

- 100 баллов – полный комплект блок-схем и описания.

- 0 баллов – неполнота или отсутствие собственных технических решений.

По разделу III баллы членов комиссии усредняются и учитываются со значимостью соответствующих показателей. Расчётный максимальный вклад одного предложения в итоговую оценку — **12 баллов из 100**: `100 × 20% × 100% × 60%`. Для всех пяти предложений — до 60 итоговых баллов. Это расчёт по указанным весам, а не дополнительная шкала; промежуточные уровни за частично выполненный комплект документом не установлены.

## Обязательный состав предложения

Ниже воспроизведён состав по п. 2.1.4 порядка оценки. Каждый перечисленный элемент должен находиться в материалах заявки.

1.  **Алгоритм (блок-схема)** действий пользователя при участии в викторине:

    - выбор викторины из списка;

    - прохождение вопросов (с вариантами ответов);

    - получение результата (количество правильных ответов);

    - начисление баллов и/или достижений;

    - возможность повторного прохождения (если допускается правилами).<br>
      Требования – согласно **п. 9.10.7** ТЗ.

2.  **Алгоритм (блок-схема)** работы системы викторины:

    - хранение банка вопросов с категориями, сложностью;

    - генерация последовательности вопросов (случайный выбор);

    - проверка ответов и подсчёт баллов;

    - ведение истории прохождений пользователя;

    - защита от повторного начисления баллов за одно прохождение;

    - административный интерфейс для управления вопросами.<br>
      Требования – в соответствии с **п. 9.10.3–9.10.5** и **9.10.10** ТЗ.

3.  **Описание последовательных шагов выполнения работ** по разработке викторины как части игровых механик:

    - проектирование модели данных;

    - разработка API для взаимодействия с мобильным приложением и сайтом;

    - создание административной панели для наполнения и настройки викторин;

    - интеграция с программой лояльности (начисление баллов, выдача достижений);

    - тестирование и обеспечение защиты от злоупотреблений.

## Когда выставляется ноль {#когда-выставляется-ноль}

По [п. 2.1.4](../../evaluation/03.md#quality-4):

1. неполнота или отсутствие собственных технических решений,

2. предложение участника закупки перефразирует Техническое задание

3. участник закупки указывает что выполнит работы надлежащим образом в соответствии с Техническим заданием,

4. предложение участника нарушает законодательство Российской Федерации.

5. предложение участника представлено не в полном объеме.

Предложение предоставляется в свободной форме. Порядок оценки прямо указывает: отсутствие информации по этому детализирующему показателю само по себе не является основанием признать заявку не соответствующей требованиям. Однако оно лишает возможности получить баллы по соответствующему показателю.

## Особенности проверки

Повторное прохождение и повторное начисление — разные операции. Порядок оценки допускает повторное прохождение, если оно разрешено правилами; ТЗ допускает настраиваемые однократные или повторные начисления. Не следует вводить безусловный запрет всех повторных попыток или всех повторных наград. Сценарии для проверки: С-09 и С-10.
