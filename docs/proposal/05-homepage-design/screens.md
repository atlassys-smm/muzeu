# Экраны, сущности и действия главной страницы

Это рабочая декомпозиция главной страницы для подготовки макета, а не готовый макет или подтверждение соответствия критерию. Основание — [п. 9.1.3](../../technical-specification/09-01.md#перечень-разрабатываемых-разделов-и-функций) ТЗ. Под экраном ниже понимается смысловая зона длинной страницы: её границы не обязаны совпадать с высотой окна. Порядок блоков сохраняется на компьютере и телефоне.

**Обозначения:** «ТЗ» — прямо заданные состав и поведение; «Проект» — предлагаемая детализация для макета и будущей модели данных, требующая согласования. Атрибуты описывают данные для интерфейса, а не окончательную схему базы данных. Данные связанных сущностей не дублируются: Hero ссылается на событие, карточки используют общие записи событий, объектов и товаров.

Для наполнения макета собрана [подборка реальных материалов музея](content.md#real-content): события, коллекции, здания, новости, промо, товары и контакты. В ней указаны источники и неподтверждённые поля; рабочие ID связывают записи с блоками ниже.

Для подключения к коду подготовлены [отдельные JSON по сущностям](content.md#json-data), включая минимум десять событий, товаров и предметов коллекции. Файлы содержат пути к локальным изображениям и ссылки между записями; порядок блоков и состояние интерфейса задаются кодом макета.

### Карта экранов

| ID | Экран / зона | Основная задача посетителя |
| --- | --- | --- |
| Г-01 | Глобальная шапка | Найти раздел, сервис, событие или вход в ЛК |
| Г-02 | Hero | Познакомиться с актуальными событиями и открыть выбранное |
| Г-03 | Афиша | Быстро выбрать событие по типу |
| Г-04 | Коллекции | Узнать о фондах и перейти к коллекции |
| Г-05 | Музейно-театральный квартал | Выбрать объект квартала или филиал |
| Г-06 | Новости и подписка | Прочитать новость и подписаться |
| Г-07 | Промо | Перейти к продвигаемому материалу |
| Г-08 | Интернет-магазин | Выбрать категорию или товар |
| Г-09 | Подвал | Найти контакты, режим работы и официальные сведения |

### Г-01. Глобальная шапка

**ТЗ:** верхняя строка экосистемы — «Магазин», «Театральная энциклопедия», «Медиа»; поиск, ЛК, RU/EN; основная навигация — меню, «Афиша», логотип, «Купить билет».

| Сущность | Атрибутивная модель |
| --- | --- |
| Логотип | ТЗ: графический знак. Проект: файл, текстовая альтернатива, ссылка на главную |
| Пункт навигации / ссылка на сервис | ТЗ: название и назначение перечисленных переходов. Проект: ID, локализованная подпись, URL, порядок, родительский пункт, признак текущего раздела |
| Поисковый запрос | ТЗ: строка поиска по основному сайту. Проект: введённый текст, язык интерфейса, состояние отправки |
| Язык интерфейса | ТЗ: RU/EN. Проект: код, подпись, признак выбранного языка, URL соответствующей версии |
| Вход в ЛК | ТЗ: ссылка на ЛК. Проект: состояние сессии «гость / авторизован», подпись и целевой URL; персональные данные в шапке не обязательны |

**Действия**

- Открыть меню и нужный раздел.
- Перейти в сервис экосистемы.
- Открыть афишу.
- Ввести и отправить поисковый запрос.
- Переключить язык.
- Перейти к авторизации или в ЛК.
- Перейти к выбору события по кнопке «Купить билет» (Проект).

Проект: «Купить билет» ведёт в афишу для выбора события, поскольку конкретное событие ещё не выбрано; точку входа нужно согласовать. Поиск ведёт на отдельную страницу результатов с фильтрацией по типам контента, предусмотренную ТЗ.

**Состояния и адаптация (Проект):** раскрытое/закрытое меню; открытая строка поиска; пустой запрос с подсказкой. На телефоне — компактная шапка и раскрываемое меню со всеми сервисными ссылками; закрытие кнопкой и Escape, возврат фокуса к вызвавшей кнопке. Необходимость закрепления шапки согласуется отдельно.

### Г-02. Hero — динамический коллаж событий

**ТЗ:** полноэкранный коллаж из нескольких образов, каждый связан с событием/выставкой; образы и заголовок сменяются; контент управляется через CMS. Клик по образу открывает обычную страницу соответствующего события.

| Сущность | Атрибутивная модель |
| --- | --- |
| Композиция Hero | ТЗ: несколько образов, сменяемый заголовок. Проект: ID, набор элементов, порядок показа, параметры смены, статус публикации |
| Элемент коллажа | ТЗ: образ, связь с событием. Проект: ID, ID события, изображение и мобильный вариант, текстовая альтернатива, кадрирование, порядок, подпись |
| Связанное событие | ТЗ: событие/выставка и его страница. Проект: ID, название, URL, доступность публикации; название берётся из записи события |

**Действия**

- Открыть соответствующее событие.
- Приостановить или возобновить движение (Проект).
- Выбрать композицию вручную (Проект).

Проект: видимая кнопка паузы/возобновления и ручной выбор композиции; синхронная смена образа, заголовка и ссылки, чтобы они относились к одному событию.

**Состояния и адаптация (Проект):** первый кадр, смена, пауза, клавиатурный фокус. При предпочтении уменьшенного движения — статичная композиция с доступными ссылками. На телефоне изображения перекомпоновываются без потери связей и читаемости; точное понимание «полноэкранного» размера с учётом шапки фиксируется в макете. При отсутствии опубликованных элементов — согласованный статичный резервный вариант; не выводить пустые ссылки. Длительности и способ смены ТЗ не задаёт.

### Г-03. Афиша

**ТЗ:** заголовок, вкладки «Все / Выставки / Экскурсии / Спектакли», ограниченный список карточек и «Смотреть все». На главной нет цен и кнопки «Купить»: покупка выполняется на странице события.

| Сущность | Атрибутивная модель |
| --- | --- |
| Вкладка типа события | ТЗ: четыре указанных значения. Проект: код, локализованная подпись, порядок, выбранное состояние |
| Карточка события | ТЗ: дата, площадка/филиал, изображение, тип, возрастная маркировка, название. Проект: ID события, URL, начало/окончание периода либо ближайший сеанс, ID площадки, текстовая альтернатива изображения |
| Подборка афиши | ТЗ: ограниченный список. Проект: лимит, порядок, правило отбора актуальных событий; количество карточек пока не определено |

**Действия**

- Переключить тип события.
- Открыть страницу события.
- Перейти в полную афишу.

Проект: при переходе «Смотреть все» сохранять выбранный тип; календарь и остальные фильтры остаются на странице афиши.

**Состояния и адаптация (Проект):** активная вкладка, загрузка, пустая выборка с переходом ко всей афише, ошибка с повтором. На телефоне — сетка в одну колонку либо согласованная компактная раскладка; вкладки доступны без обрезания подписей. Длинные названия переносятся; возрастная маркировка и площадка остаются видимыми.

### Г-04. Коллекции

**ТЗ:** текст-анонс фондов, «Узнать больше» → внутренняя страница «Коллекция», декоративный параллакс. Интерактивный просмотр экспонатов находится на внутренней странице.

| Сущность | Атрибутивная модель |
| --- | --- |
| Анонс фондов | ТЗ: текст и переход. Проект: ID, заголовок, текст анонса, подпись кнопки, URL целевой страницы |
| Декоративная композиция | ТЗ: оформление с параллаксом. Проект: изображения, кадрирование для разных ширин, признак декоративности, параметры движения; для значимых изображений — текстовая альтернатива |

**Действия**

- Перейти на внутреннюю страницу коллекции.

Самостоятельные действия над экспонатом в этом блоке не предусматриваются.

**Состояния и адаптация (Проект):** обычная и статичная композиции; параллакс отключается при уменьшенном движении. На телефоне текст, кнопка и изображения выстраиваются последовательно, без перекрытия. Нужно уточнить точную целевую страницу: ТЗ использует названия «Коллекции» и «Коллекция».

### Г-05. Музейно-театральный квартал

**ТЗ:** карточки объектов, слайдер с ручной пагинацией, переключатель «Филиалы», раскрывающий список. Автоматической прокрутки нет.

| Сущность | Атрибутивная модель |
| --- | --- |
| Объект квартала / филиал | ТЗ: адрес, бейджи доступности/удобств, фото, «Узнать больше». Проект: ID, название, тип объекта, URL страницы, текстовая альтернатива фото, порядок |
| Бейдж доступности / удобства | ТЗ: обозначение свойства объекта. Проект: код, текстовая подпись, иконка; значения заполняются по подтверждённым сведениям музея |
| Слайдер объектов | ТЗ: ручная пагинация. Проект: список ID объектов, текущая позиция, количество позиций |
| Список филиалов | ТЗ: раскрывается переключателем. Проект: элементы «ID филиала, название, URL», состояние раскрытия |

Содержание для карточек: [пространства квартала, сведения из интернета](content.md#quarter-internet). [Пояснение и предлагаемый словарь бейджей](content.md#place-badges): короткие подписи об условиях посещения; перечень ТЗ не устанавливает, фактические значения нужно подтверждать для каждого объекта.

**Действия**

- Вручную выбрать предыдущий или следующий объект либо позицию.
- Открыть страницу объекта.
- Раскрыть или свернуть список филиалов.
- Выбрать филиал.

Проект: стрелки, доступная пагинация и свайп как дополнительный способ; свайп не заменяет кнопки.

**Состояния и адаптация (Проект):** первая/промежуточная/последняя позиция; недоступная стрелка на границе; один объект без лишней навигации; раскрытый список. На телефоне — одна основная карточка, адрес и бейджи не скрываются. При пустом списке — сообщение; при ошибке — повтор загрузки.

### Г-06. Новости и подписка

**ТЗ:** ограниченный список новостей (изображение, заголовок, дата), «Смотреть все» и подписка на рассылку.

| Сущность | Атрибутивная модель |
| --- | --- |
| Карточка новости | ТЗ: изображение, заголовок, дата. Проект: ID, URL полного текста, текстовая альтернатива, дата публикации |
| Подборка новостей | ТЗ: ограниченный список. Проект: лимит и правило сортировки; количество карточек согласуется |
| Форма подписки | ТЗ: возможность подписки. Проект: email, состояние ввода/отправки, результат, ссылки на применимые документы и согласуемые элементы согласия |

**Действия**

- Открыть новость.
- Перейти ко всем новостям.
- Ввести email.
- Отправить запрос на подписку.
- Подтвердить адрес по ссылке из письма, если выбран такой механизм (Проект).

Проект: проверить формат на клиенте и сервере; показать понятный результат. Если выбран механизм подтверждения адреса, сообщить о необходимости перейти по письму, не выдавая отправку письма за завершённую подписку. Способ подтверждения и тексты согласий пока не установлены.

**Состояния и адаптация (Проект):** пустое поле, некорректный email, отправка, принятый запрос, ошибка сервиса с повтором без потери ввода. Пустая лента не мешает подписке. На телефоне поле и кнопка располагаются вертикально; ошибка связана с полем и доступна экранному диктору.

### Г-07. Промо-блок

**ТЗ:** управляемый через CMS слайдер материалов: изображение, заголовок, описание, кнопка.

| Сущность | Атрибутивная модель |
| --- | --- |
| Промо-материал | ТЗ: изображение, заголовок, описание, кнопка. Проект: ID, подпись и URL кнопки, текстовая альтернатива, мобильное изображение, порядок, статус и период публикации |
| Промо-слайдер | ТЗ: набор материалов. Проект: текущая позиция, количество слайдов, ручной режим переключения |

**Действия**

- Переключить промо-материал.
- Перейти по кнопке материала.

Проект: ручная навигация без автопрокрутки; в отличие от квартала, это наше решение, а не прямое ограничение ТЗ.

**Состояния и адаптация (Проект):** один материал без навигации, несколько материалов с пагинацией, длинное описание; при отсутствии материалов — резервный материал либо скрытие по согласованному правилу. В полном демонстрационном макете блок обязательно присутствует. На телефоне текст выносится из изображения, если иначе нельзя обеспечить читаемость.

### Г-08. Витрина интернет-магазина

**ТЗ:** вкладки «Все / Одежда / Аксессуары / Сувениры», карточки с изображением, категорией, названием и ценой; «Смотреть все» → магазин.

| Сущность | Атрибутивная модель |
| --- | --- |
| Категория товара | ТЗ: указанные вкладки. Проект: ID/код, локализованная подпись, порядок, URL категории магазина |
| Карточка товара | ТЗ: изображение, категория, название, цена. Проект: ID товара, URL, числовая цена, валюта, текстовая альтернатива, доступность публикации |
| Подборка товаров | ТЗ: витрина. Проект: список ID, лимит, порядок, источник актуальных данных и состояние загрузки |

**Действия**

- Переключить категорию.
- Открыть товар в магазине.
- Перейти в интернет-магазин.

Проект: «Смотреть все» сохраняет выбранную категорию; покупка и выбор вариантов товара происходят в магазине. Добавление в корзину на главной ТЗ не задаёт.

**Состояния и адаптация (Проект):** загрузка, нет товаров категории, ошибка/недоступность магазина с возможностью прямого перехода. Отсутствующую цену не заменять нулём; правило скрытия карточки или подписи согласовать. На телефоне — компактная сетка с читаемыми названиями и ценой; количество колонок определяется при компоновке.

### Г-09. Подвал

**ТЗ:** навигация, часы работы, контакты, адрес, подписка, соцсети/мессенджеры, логотипы Минкультуры РФ и Культура.РФ, правовые ссылки. Состав обязательных страниц и доступ к ним описаны в [п. 9.1.4](../../technical-specification/09-01.md#размещение-обязательных-правовых-технических-и-официальных-страниц).

| Сущность | Атрибутивная модель |
| --- | --- |
| Группа навигации | ТЗ: навигационные ссылки. Проект: ID, заголовок, упорядоченный набор пунктов с подписью и URL |
| Контакт / адрес / режим работы | ТЗ: контактные сведения, адрес, часы. Проект: организация или объект, телефон, email, текст адреса, расписание и исключения; сведения не должны создавать впечатление единого режима всех филиалов |
| Социальная или официальная ссылка | ТЗ: соцсети/мессенджеры и два официальных логотипа. Проект: название, URL, иконка/логотип, доступная подпись |
| Правовая / официальная страница | ТЗ: актуальная версия документа в CMS без авторизации. Проект: ID, согласованное название, URL, версия/дата актуальности для управления содержанием |
| Подписка | ТЗ: подписка на новости. Проект: общий компонент и единый процесс с Г-06, уникальные ID полей при двух формах на странице |

**Действия**

- Перейти в раздел сайта.
- Открыть документ.
- Позвонить по контактному телефону.
- Написать на контактный email.
- Открыть социальную или официальную страницу.
- Отправить запрос на подписку.

Обязательные страницы доступны максимум в один клик из подвала: карта сайта, политика обработки ПДн, согласия и их версии, сведения об организации, правовая информация, официальные документы, годовые отчёты, противодействие коррупции. Уточнённый список для основного сайта устанавливается в ЧТЗ.

**Состояния и адаптация (Проект):** длинные подписи и адреса, состояния формы подписки. На телефоне колонки становятся вертикальными группами; обязательные ссылки остаются непосредственно доступными, без дополнительного раскрытия вложенных меню.

### Общие атрибуты и правила

Предлагаемые служебные атрибуты CMS для редактируемого контента: стабильный ID, статус публикации, порядок, языковые варианты, даты публикации/снятия, связанные объекты и медиаресурсы. Не все поля обязательны для каждого типа: например, срок размещения применим к промо, но не обязан задаваться для постоянного контакта. Это проектная модель, которую предстоит сверить с существующей CMS.

Для изображения предусматриваются источник файла, размеры, варианты кадрирования, текстовая альтернатива либо признак декоративности. Для ссылки — подпись и адрес назначения; для даты и цены — структурированное значение, из которого формируется локализованное представление. Недостающие сведения не заполняются вымышленными фактами о музее.

По [п. 13.2–13.6](../../technical-specification/13.md#единая-дизайн-система) и [Приложению № 3](../../technical-specification/appendix-03.md) в комплекте макетов нужно показать состояния компонентов: обычное, наведение, фокус, активное, недоступное, загрузка, пустой результат, ошибка; длинный текст и недоступность внешнего сервиса. Применять состояния по смыслу: статическому тексту не нужен loading, а кнопке повтора — нужен видимый фокус.

RU/EN обязательны для интерфейса. Перевод музейного контента не входит в обязанность Подрядчика; правило показа русского материала или сообщения об отсутствии перевода согласуется с Заказчиком. Переключение языка по возможности сохраняет контекст. Доступность включает клавиатуру, видимый фокус, контраст, текстовые альтернативы и управление движением; сведения о доступности объектов нельзя передавать только цветом или иконкой.

### Что нужно определить перед визуальным макетом

1. Получить брендбук и ранее утверждённый макет, на который ссылается [п. 9.1.1](../../technical-specification/09-01.md#дизайн-макеты-основного-сайта). Их наличие пока не подтверждено; соответствие им не проверено.
2. Подтвердить меню, URL сервисов, маршрут кнопки «Купить билет» и целевую страницу блока коллекций.
3. Утвердить [собранную подборку реального содержания](content.md#real-content), закрыть отмеченные в ней пробелы и получить основания использования изображений. Зафиксировать лимиты подборок, порядок и правила актуальности.
4. Подтвердить модель подписки, тексты и элементы согласий, контакты, режимы работы и перечень официальных ссылок. До этого форма остаётся проектным вариантом.
5. Согласовать правила движения, резервные состояния, ширины компоновки и переход от десктопа к телефону. Показать полные варианты главной; планшетный вариант добавить, если поведение нельзя однозначно вывести из остальных.

Этот разбор покрывает подготовку структуры. Иллюстрированная концепция, подробные визуальные макеты, палитра с кодами и обоснованием, адаптивные варианты ещё должны быть подготовлены и проверены по [матрице соответствия](compliance.md).
