## 7.1. Требования к модели доступа {#требования-к-модели-доступа}


<ul>
<li><p>принцип минимально необходимых полномочий;</p></li>
<li><p>разделение функций редактирования и публикации для критичного
контента;</p></li>
<li><p>отдельные административные учетные записи;</p></li>
<li><p>многофакторная аутентификация для привилегированных
ролей;</p></li>
<li><p>регистрация входов, изменений прав, публикаций, выгрузок и
критичных операций;</p></li>
<li><p>периодическая проверка актуальности прав;</p></li>
<li><p>оперативное прекращение доступа уволенных сотрудников и
завершивших работу подрядчиков.</p></li>
</ul>


## 7.2. Матрица ролей и прав доступа {#матрица-ролей-и-прав-доступа}


<p>Подрядчик обязан разработать, согласовать с Заказчиком и реализовать
матрицу ролей и прав доступа для всех административных и внутренних
компонентов Экосистемы.</p>
<p>Минимальный состав ролей и полномочий устанавливается Приложением № 7
к настоящему ТЗ. Матрица уточняется по результатам обследования без
исключения предусмотренных ролей, ограничений и требований к аудиту.</p>
<p>Для каждой роли должны быть определены права на:</p>
<ul>
<li><p>просмотр;</p></li>
<li><p>создание;</p></li>
<li><p>изменение;</p></li>
<li><p>согласование;</p></li>
<li><p>публикацию;</p></li>
<li><p>архивирование;</p></li>
<li><p>удаление;</p></li>
<li><p>экспорт;</p></li>
<li><p>изменение справочников и настроек;</p></li>
<li><p>просмотр журналов;</p></li>
<li><p>управление пользователями и правами.</p></li>
</ul>
<p>Совмещение ролей допускается только при отсутствии недопустимого
конфликта полномочий. Операции публикации критичного контента, изменения
правил лояльности, ручной корректировки бонусов, экспорта персональных
данных и назначения административных прав должны журналироваться.</p>
